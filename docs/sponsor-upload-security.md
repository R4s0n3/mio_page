# Public sponsor logo uploads

Public sponsor checkout stays enabled. Only PNG, JPEG, GIF, and WebP images up
to 2 MB are accepted. SVG, HTML, archives, PDFs, and other file types are rejected.
Names, extensions, MIME declarations, and file signatures must agree.

Before storage, Sharp fully decodes accepted raster input and re-encodes a new
image. Static images become PNGs; animations become freshly encoded GIFs. Input
metadata is not preserved, original visitor bytes are never uploaded to the CDN,
and filenames are generated by the server. Logo dimensions are limited to
4096 × 4096 per frame, 100 frames, and 16 Mi total pixels across frames. Outputs
fit within 1024 × 1024 and must remain below 2 MB.

Multipart requests are capped at 3 MB even without Content-Length, with a
10-second body-read deadline. Decoding is limited to two active operations per
server instance and a five-second image-processing budget. Keep proxy request
limits/rate limits and runtime memory/CPU limits in place as deployment controls;
the in-process concurrency limit is not a distributed rate limiter.

Deploy the public website and CDN updates together. The CDN update accepts GIF
signatures in S3 mode as well as its existing disk mode, so rebuilt animations
work in either configuration. No database schema change or new secret is needed.
This change applies to new public sponsor uploads; existing stored files are not
modified. Owner-only dashboard uploads remain a separate workflow.

Re-encoding is a defense against executable metadata, appended payloads, and
malformed inputs, not a guarantee that every malicious file or image-processor
exploit is detectable. Keep Sharp/libvips updated. Visual content moderation and
an antivirus/quarantine service are separate measures if needed.
